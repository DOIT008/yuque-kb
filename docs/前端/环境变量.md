# 环境变量

> 来源：语雀「前端」 · [查看原文](https://www.yuque.com/alipayqxigqpgusn/rs8s8g/zu5ufc)

我们在开发的时候开发配置和生产配置往往是不一样的，那么如何区分这两种配置呢？

在项目根目录下创建`.env.development`，`.env.production`文件，里面的变量需要以`VITE_`开头，例如，而且这些文件并不需要引用，直接就可以访问了

## 代码示例

```plain
// .env ，这里声明的变量在任何环境中都能被访问的到
VITE_BASE_URL = /api

// .env.development,只有在dev环境中才能被访问
VITE_MODE = production
VITE_URL = http://www.baidu.com

// .env.production，在生产环境中被访问
# 注释的话前面要用“#”开头
VITE_MODE = production
VITE_URL = http://www.sina.com

```

vite在开发时候默认是`development`，在生产的时候使用的是`production`，

在组件中访问上述变量，**当然也可以在任何一个JS文件中：**

```vue
<script>
  // import.meta.env，其实这个对象包含很多信息，可以打印出来
  console.log(import.meta.env.VITE_MODE);
</script>
```

其实在`.vue`文件中也能访问。

```vue
<script>
  // import.meta.env，其实这个对象包含很多信息，可以打印出来
  console.log(import.meta.env.MODE);
</script>
```

> 在Vue2.x中使用的是`process.env.xx`来进行访问

## 命令中的应用

当然我们可以在命令中通过`--mode`来限定某些命令用哪种模式，当然这些都是在`package.json`中使用的。例如：

```json
{
"scripts": {
    "dev": "vite --mode production",
    "build": "vue-tsc --noEmit && vite build",
    "preview": "vite preview"
  },
}
```

上述默认情况下当运行`npm run dev`的时候，使用的是development环境，也就是说读取的是`.env.development`中的变量，但是经过上面的修改就变成了使用`.env.production`中的变量。
