在某种意义上说，接口就是一个工具，去让我们的代码符合我们定义的某种契约，是为了校验代码才存在的。主要左作用是在开发的时候约束代码合规。

## 接口定义

定义接口的时候要使用`interface`关键字，结构是`interface {...}`例如：

## 代码示例

```ts
// 定义了一个接口Girl，约束某个对象必须包含name,age,bust三个属性
interface Girl {
  name: string;
  age: number;
  bust: number;
  say(n:string):void;
}
// girl是一个对象
function getResume(girl: Girl) {
  console.log(girl.name, girl.age, girl.bust);
  girl.say(girl.name)
}
getResume({ name: "谢大脚", age: 18, bust: 98,say(n:string){
console.log(n)
} });
```

## 可选属性

上述每个属性都是必填的，但如果某个属性是可有可无的呢？

其实TS早就为我们想到了，只需要在属性名后面加一个`?`即可：

```ts
// sex属性可有可无
interface Girl {
  name: string;
  age: number;
  bust: number;
  sex?:string
}

// 这样即便girl中有没有sex属性，都不会报错
function getResume(girl: Girl) {
  console.log(girl.name, girl.age, girl.bust);
}
getResume({ name: "谢大脚", age: 18, bust: 98,sex:'女' });
```

函数的返回值也可以是接口，例如：

```ts
// 接口约束函数参数
interface SquareConfig {
    color?: string;
    width?: number;
}
// 将接口约束函数返回值
interface SquareArea {
    color: string;
    area: number;
}
function createSquare(config: SquareConfig): SquareArea {
    let newSquare = { color: 'white', area: 100 };
    if (config.color) {
        newSquare.color = config.color;
    }
    if (config.width) {
        newSquare.area = config.width * config.width;
    }
    return newSquare;
}
let _config = { color: 'green' };
console.log(createSquare(_config));

let _config1 = { color: 'blue', width: 200 };
console.log(createSquare(_config1));
```

## 只读属性

顾名思义，就是接口定义的某个属性是只读的，不能更改，和普通的接口定义唯一的区别就是属性前面加了一个`readonly`，例如：

```ts
// 定义接口Point
interface Point {
    readonly x: number;
    readonly y: number;
}

let point: Point = {
    x: 30,
    y: 30
};
point.x = 31; // 报错，因为x属性是只读属性
```

## 额外的属性检查

其实就是可以让我们添加符合某种条件的任意属性（除了已经存在的必填属性），使用`[propName:string]:any`，例如：

```ts
interface Girl {
  name: string;
  age: number;
  bust: number;
  sex?: string;
  [propName: string]: any;//表示额外的属性名是string类型，其属性值可以是任何类型
}

//
function getResume(girl: Girl) {
  console.log(girl.name, girl.age, girl.bust);
  girl.sayhello && girl.sayhello(girl.name); // 如果存在sayhello就执行
}

getResume({
  name: "谢大脚",
  age: 18,
  bust: 98,
  sayhello: (name: string): void => {
    //额外的属性
    console.log("hello", name);
  }
});
```

## 约束数组

数组一般使用`type`进行约束，但也可以使用接口，例如：

```ts
interface Person {
    name: string;
    age: number;
}

let personArr: Array<Person> = [{ name: '张三', age: 13 }];
```

## 分类

### 函数类型

当然如果接口只能定义某个对象符合某种契约，那应用面也太狭窄了：

> 接口也可用来为某个函数定义契约，为了使用接口表示函数类型，我们需要给接口定义一个调用签名。 它就像是一个只有参数列表和返回值类型的函数定义。参数列表里的每个参数都需要名字和类型。

例如：

```ts
// 定义一个函数接口，表示某个函数的参数必须有三个参数，并且参数的类型也已经确定了，而且还没有返回值,当然下面的参数只是形参
interface selfDesc {
  // 调用签名
  (name: string, age: number, home: string): void;
}

let _selfDesc: selfDesc;
_selfDesc = (name: string, age: number, home: string): void => {
  console.log(`哈喽，大家好！我是${name},我今年${age}岁了，我来自${home}`);
};
// 执行

_selfDesc("刘亦菲", 19, "美国"); //哈喽，大家好！我是刘亦菲,我今年19岁了，我来自美国
```

又例如：

```ts
interface FindIndexStr {
    (sourceStr: string, index: number): string;
}

let findIndexStr: FindIndexStr;
findIndexStr = function (sourceStr: string, index: number) :string{
    return sourceStr.charAt(index);
};

console.log(findIndexStr('张三是个大帅哥', 5));
```

在实际使用接口来约束函数的时候，参数名可以和接口中不一样（毕竟函数在定义的时候，参数只是形参）,所以上述的例子可以写为：

```ts
interface FindIndexStr {
    (sourceStr: string, index: number): string;
}

let findIndexStr: FindIndexStr;
// 注意这里第一个参数是s，第二个参数是i
findIndexStr = function (s: string, i: number) {
    return s.charAt(i);
};

console.log(findIndexStr('张三是个大帅哥', 5));
```

### 类类型

顾名思义，就是让某个`class`去符合某种契约，需要使用`implements`关键字，例如：

```ts
// 定义接口
interface dateInterface {
  time: string; //其实这里可有可无
  getTime(); //表示有getTime函数，主要起到描述作用
  resetTime(t: string): void; //表示有resetTime函数,主要起到描述作用，没有返回值
}

// 让Time类符合dateInterface接口
class Time implements dateInterface {
  time: string;//属性，constructor中的属性必须先在这里定义
  getTime() {// 真正的实现
    console.log(this.time);
  }
  resetTime(t: string) { // 真正实现
    
  }
  constructor(t: string) {
    this.time = t;
    // constructor是在创建Time实例的时候就立即执行的，所以time属性的赋值，可以在这时候进行设置
  }
}

// 创建实例
let _time = new Time("2021-05-18");
_time.resetTime("2021-05-18");
console.log(_time);
```

当然一个类可以同时被多个接口所约束，其实就是这样：

```ts
class IDate implements IDateInterface,ItimeInterface...{

}
// 那么此时IDate这个类要满足上述两个接口的并集即可
```

例如

```ts
interface IIndex {
    sayTime(): string;
}
class ITime implements IIndex, IClass {
    time: string;
    constructor() {
        this.time = '晚上11点啦';
    }
    sayDate(): void {}
    sayTime(): string {
        return '晚上十一点啦';
    }
}
let itime = new ITime();
console.log(itime);
```

### 混合类型

有时你会希望一个对象可以同时具有上面提到的多种类型。一个例子就是，一个对象可以同时做为函数和对象使用，并带有额外的属性。其实在使用的时候会将接口中的额外属性当作函数的属性去定义，例如：

```ts

// 你会发现Counter里面既有函数的定义又有其他属性的定义，这就是混合类型
interface Counter {
    (start: number): string;
    interval: number;
    reset(): void; // 属性，只不过值是函数
}

//使用，定义一个函数，函数也有属性
function getCounter(): Counter {
  // 定义函数
    let counter = <Counter>function (start: number): string {
        return start.toString();
    };
  // 函数的属性
    counter.interval = 123;
  // 函数的属性
    counter.reset = function () {
        counter.interval = 456;
    };
    return counter;
}
let c = getCounter(); // 就是一个函数
console.log(c(900)); // 执行的是(start: number)：string这个函数
c.interval = 888;
console.log(c.interval); //888
c.reset();
console.log(c.interval); // 456
```

## 接口继承🏁

其实就是一个接口继承于另一个接口，使用`extends`关键字，例如：

```ts
// 继承
interface animal {
  bark(): void; // 不能具体实现，指定定义有这个函数，返回值是啥类型
  selfDesc(name: string, age: number): void;
}
// dog的接口的约束条件继承了animal，也就是说必须包含bark函数
interface dog extends animal {
  name: string;
  age: number;
}

let _dog: dog = {
  name: "大黄",
  age: 4,
  bark() {
    console.log("汪汪");
  },
  selfDesc(name: string, age: number) {
    console.log(name, age);
  },
};
```

也可以一下子继承多个接口，用逗号分开就行了。

## 接口继承类(不常用)

当接口继承了一个类类型时，它会继承类的成员但不包括其实现。 就好像接口声明了所有类中存在的成员，但并没有提供具体实现一样。 接口同样会继承到类的`private`和`protected`成员。 这意味着当你创建了一个接口继承了一个拥有私有或受保护的成员的类时，这个接口类型只能被这个类或其子类所实现（`implement`）。

当你有一个庞大的继承结构时这很有用，但要指出的是你的代码只在子类拥有特定属性时起作用。 这个子类除了继承至基类外与基类没有任何关系。 例：

```ts
class Control {
    private state: any;
}

interface SelectableControl extends Control {
    select(): void;
}

class Button extends Control implements SelectableControl {
    select() { }
}

class TextBox extends Control {
    select() { }
}

// 错误：“Image”类型缺少“state”属性。
class Image implements SelectableControl {
    select() { }
}

class Location {

}
```

在上面的例子里，SelectableControl包含了Control的所有成员，包括私有成员state。 因为 state是私有成员，所以只能够是Control的子类们才能实现SelectableControl接口。 因为只有 Control的子类才能够拥有一个声明于Control的私有成员state，这对私有成员的兼容性是必需的。

在Control类内部，是允许通过SelectableControl的实例来访问私有成员state的。 实际上， SelectableControl接口和拥有select方法的Control类是一样的。 Button和TextBox类是SelectableControl的子类（因为它们都继承自Control并有select方法），但Image和Location类并不是这样的。

## 接口的嵌套（使用时）

我们知道接口是为了约束数据而存在的，在某种程度上可以作为数据类型，那么这也就意味着可以进行接口嵌套，例如：

```ts
// interface
interface Al {
  picUrl: string;
}
interface Value {
  id: number;
}
export interface ICurrentPlayInfo {
  al: Al;
  name: string;
  value: Value;
}

let currentPlayInfo: ICurrentPlayInfo = {
  al: {
    picUrl: "http://xxx",
  },
  name: "木兰",
  value: {
    id: 344,
  }
};

```

> 同理type关键字也可以咯，只不过写法不一样而已

## 索引签名💗

索引签名（Index Signature）是 TypeScript 中一种强大的类型定义方式，它允许我们定义对象或数组的键和值的类型关系。

### 基本语法

索引签名有两种基本形式：**字符串索引签名和数字索引签名。**

```tsx
interface StringIndexInterface {
  [key: string]: string;
}

// 使用示例
const obj: StringIndexInterface = {
  name: "Alice",
  email: "alice@example.com"
};
```

 

```tsx
interface NumberIndexInterface {
  [index: number]: string;
}

// 使用示例
const arr: NumberIndexInterface = {
  0: "first",
  1: "second",
  2: "third"
};
```

### 索引签名规则

1.  索引签名参数名（如 key 或 index ）可以是任意名称，不影响类型定义。
2.  索引签名必须使用 string 或 number 类型作为键的类型。
3.  如果同时定义了字符串索引签名和数字索引签名，字符串索引签名的值类型必须是数字索引签名值类型的子类型。

```tsx

interface BothIndexInterface {
  [key: string]: string;  // 字符串索引签名
  [index: number]: string; // 数字索引签名，值类型必须与字符串索引签名相同或为其子类型
}
```

### 使用场景

1.  错误码映射

```tsx
interface ErrorCode {
  [key: number]: string
}

const errorCode: ErrorCode = {
  401: '认证失败，无法访问系统资源',
  403: '当前操作没有权限',
  404: '访问资源不存在',
}
```

2.  动态属性对象

```tsx
interface DynamicObject {
  [key: string]: any;
}

function processConfig(config: DynamicObject) {
  // 可以处理任何属性名的配置
  for (const key in config) {
    console.log(`${key}: ${config[key]}`);
  }
}

processConfig({
  apiUrl: "https://api.example.com",
  timeout: 5000,
  retries: 3
});
```

3、和泛型结合

```tsx
interface GenericDictionary<K extends string | number, V> {
  [key: K]: V;
}

// 使用字符串键和数字值
const stringToNumber: GenericDictionary<string, number> = {
  "one": 1,
  "two": 2,
  "three": 3
};

// 使用数字键和字符串值
const numberToString: GenericDictionary<number, string> = {
  1: "one",
  2: "two",
  3: "three"
};
```

## 总结

接口就是为了约束数据，被约束的数据有哪些属性和方法在书写代码的时候就很清晰的展示出来，而不是自己去找有那些属性方法等，这就是TS的魅力，这就是强类型的魅力。
