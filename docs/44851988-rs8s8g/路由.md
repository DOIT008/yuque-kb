## 配置

路由配置文件router/routes.ts

```js
import { RouteRecordRaw } from "vue-router";
const routes: Array<RouteRecordRaw> = [
  {
    path: "/",
    name:'main',
    redirect: "/todo-list",//表示初始化的时候重定向到path为/todo-list的路由并显示其对应的组件
  },
  {
    path: "/todo-list",
    name: "todoList",
    // 路由懒加载，当然你也可以直接先把对应的组件先引过来再说
    component: () => import("../pages/todo-list.vue"),
    meta:{// 路由元信息，组件中route.meta.title访问
  			title:'xxx',
    		icon:'icon-xxx'
  	}
  },
  {
    path: "/hello",
    name: "hello",
    // 路由懒加载
    component: () => import("../pages/hello.vue"),
  },
  // 一般放到最后，啥也没匹配到的时候使用404组件
  { path: "/:pathMatch(.*)*",name:'NotFound', component: NotFound }
];
```

​  

路由入口文件 `router/index.ts`

```js
import {createRouter,createWebHashHistory} from "vue-router";
// import * as VueRouter from "vue-router"; 可以查看VueRouter里面都有啥

import routes from "./routes"; // routes是路由的配置对象，各种各样的路由配置[{path，component}]

// 创建router实例
const router = createRouter({
  history: createWebHashHistory(),// 采用hash模式：/#/path （建议用这个），相当于原来的mode:'hash'
  // history:createWebHistory()// 采用hsitory模式：域名/path,相当于原来的mode:'history'
  // history:createMemoryHistory()// 采用abstract模式，一般用于服务端渲染，相当于原来的mode：'abstract'
  routes,// 传入routes来初始化router对象
});
// 路由全局守卫
router.beforeEach((to, from, next) => {});
// 导出以供在main.ts入口处使用
export default router;
```

main.ts

```js
import { createApp, reactive, toRefs, h } from "vue"; // 引入createApp函数
import App from "./App.vue"; // 其实其实就是一个对象
import "./index.css";
import store from "./store/index";
// 拿到路由对象
import router from "./router/index";
// 执行挂载进行实例化

const app = createApp(App);
// 使用路由
app.use(router);

app.use(store);
app.mount("#app");

```

## history的模式参数

上述路由对象中history的值，无论是`createWebHashHistory()`还是`createWebHistory()`，其实里面可以传参数`base`的，以`createWebHashHistory()`模式为例：

```js
const router = createRouter({
  history: createWebHashHistory("/directory"),
  routes,
});
//在这种模式下，将来在访问路由的时候，就会全局加一个/directory，例如；原来的localhost:3000/#/about,现在这样也可以访问localhost:3000/directory/#/about

const router = createRouter({
  history: createWebHistory("/directory"),
  routes,
});
//在这种模式下，将来在访问路由的时候，就会全局加一个/directory，例如；原来的localhost:3000/about,现现在访问的时候只能是localhost:3000/directory/about（即便是你输入的是localhost:3000/about）
```

> 其实这个base参数相当于原来路由对象的base属性

## 通配符

通常我们在写路由的配置对象的时候，一般后面都会追加一个能匹配所有情况的路由：

```js
 { path: "*",name:'NotFound', component: NotFound },
```

但是在vue-router4.x中，上述的这种配置不生效了，便成了类似于这种模式（**记住就好了**）：

```js
{ path: "/:pathMatch(.*)*",name:'NotFound', component: NotFound },
```

## router.isReady()替代onReady

在服务端渲染的时候一定会用到`onReady`（因为服务端渲染的路由都是后台返回的肯定是异步的，既然是异步的那么咱们就一定要知道啥时候完成了），但是现在`onReady`所做的事情被`isReady`所替代了，其返回一个`promise`，所以你懂了吧：

```js
router.isReady().then(res=>{}).catch(err=>{})
```

## scrollBehavior

想想这样的一个场景，我们在a路由下浏览页面时滚动到了某个位置，我我们想在其他路由下页滚动到相应的位置怎么办？这时候就可以用到`scrollBehavior`了,基本配置如下，更多的可以参考官网：

```js
const router = createRouter({
  history: createWebHistory("/directory"),
  scrollBehavior(to,from,savedPosition){
    // savedPosition 一个对象，其实系统会默认保存上个路由滚动条的位置
    // 如果有这个位置，使用该位置，如果没有就到0
    if(savedPosition){
      return savedPosition
    }else{
    	return {left:0,top:0}
    }
    
  }
  routes,
});
```

## router-view和keep-alive结合

之前我们为了能缓存路由，通常会在`<router-view/>`的外部加一个`<keep-alive/>`标签，如下：

```html
<keep-alive>
  <router-view></router-view>
</keep-alive>
```

但是在vue-router4.x中废弃了这种写法，取而代之的更易懂的这种写法：

```vue
<router-view v-slot="{ Component,route }">
  <transition>
    <keep-alive>
    <component :is="Component" v-if="route.meta.keepalive==true"  :key="route.path" />
    </keep-alive>
    <component :is="Component" v-if="route.meta.keepalive==false"  :key="route.path" />
    </transition>
</router-view>
```

## router-link标签删除的属性

### 2\. tag/event，一般是成对儿出现的

默认情况下`<router-link/>`标签渲染出来的是一个`<a/>`标签，但是如果我们想渲染出一个自定义标签呢？

之前，我们是在该标签上添加`tag`和`event`属性，比如：

```html
<router-link to="" tag="span" event="dblclick"></router-link>
```

现在要实现同样的功能，你可以标准化这样：

```html
// navigate 导航函数，人家已经实现好了
// isActive 当前路由是否是激活状态
// custom 属性表示使用自定义标签
<router-link to="" custom v-slot="{ navigate,isActive }">
    <span @click="navigate">xxx</span>// navigate可以实现一些自定义功能，但是这种方式往往意味着自己实现跳转
  </router-link>
```

 

```ts
const router = createRouter({
  history: createWebHashHistory(),
  routes,
});
```

### 3\. exact（不常用）

之前表示完全匹配的一个属性，现在如果想实现完全匹配你得自己写

## router省略的属性

1.  mixin中的路由守卫会被忽略（一个草案）
2.  reouter.match方法被替代，使用router.resolve解决
3.  移除router.getMatchedComponents()
4.  首屏导航在内的所有导航都是异步的，也就意味着马，如果你想在首屏渲染的时候你想加个动画，可以采取着中方法:

```vue
app.use(router);
router.isReady().then(()=>{
	app.mount('#app')
})
```

## CompositionAPI访问

因为我们在 setup 里面没有访问`this`，所以我们不能再直接访问 `this.$router` 或 `this.$route`。作为替代，我们使用 `useRouter` 函数：

```js
// 某个组件
import { useRouter, useRoute } from 'vue-router'

export default {
  setup() {
    const router = useRouter() // 路由实例对象
    const route = useRoute() //这里route应该是当前路由的配置对象，里面会有param或query参数

    function pushWithQuery(query) {
      router.push({
        name: 'search',
        query: {
          ...route.query,
        },
      })
    }
  },
}
```

要拿到路由中的参数，**要先使用**`**toRaw**`**将**`**route**`**对象转化为普通对象**，然后访问其中的属性即可：

```ts
import { defineComponent, onMounted, toRaw } from "vue";
import { useRoute,useRouter } from "vue-router";
onMounted(() => {
   console.log(toRaw(route).query.value);
 });
```

## 监听route变化

route 对象是一个响应式对象，所以**它的任何属性都可以被监听**，但你应该**避免监听整个** **route** 对象：

```js
import { useRoute } from 'vue-router'

export default {
  setup() {
    const route = useRoute()
    const userData = ref()

    // 当参数更改时获取用户信息
    watch(
      () => route.params,// route.query等
      async newParams => {
        userData.value = await fetchUser(newParams.id)
      },
     //  {deep:true,immediate:true}
    )
    
  }
```

请注意，在模板`<template>`中我们仍然可以访问 `$router` 和 `$route`，所以不需要在 `setup` 中返回 `router` 或 `route`。

## 路由守卫

  

在CompositionAPI种的`setup`函数中，你可以使用`onBeforeRouteLeave`, `onBeforeRouteUpdate`两个钩子，因为只有这两个钩子是公开的（组件内的守卫）：

```js
import { onBeforeRouteLeave, onBeforeRouteUpdate } from 'vue-router'

export default {
  setup() {
    // 与 beforeRouteLeave 相同，无法访问 `this`
    onBeforeRouteLeave((to, from) => {
      const answer = window.confirm(
        'Do you really want to leave? you have unsaved changes!'
      )
      // 取消导航并停留在同一页面上
      if (!answer) return false
    })

    const userData = ref()

    // 与 beforeRouteLeave 相同，无法访问 `this`
    onBeforeRouteUpdate(async (to, from) => {
      //仅当 id 更改时才获取用户，例如仅 query 或 hash 值已更改
      if (to.params.id !== from.params.id) {
        userData.value = await fetchUser(to.params.id)
      }
    })
  },
}
```

### 1\. 全局路由守卫

说白了只要是路由发生变化就会触发的全局钩子函数，一般在配置路由对象的文件中写(因为只有那里才会用到router)：

```js
router.beforeEach((to, from, next) => {});//next是可选参数，可写可不写，return false是取消导航，如果返回值为true或者是undefined意味着通过验证
router.afterEach((to, from, next) => {});
```

### 2\. 路由独享守卫

表示只有切换到该路由的时候才会触发的钩子函数

```js
 const routes = [
        {
            path:"/home",
            name:"home",
            component:Home,
            beforeEnter:(to,from) =>{
                //to是当用户点击进入当前页面的时候,我们可以进行一些拦截设置
                //from当来自其他页面进入当前页面的时候，我们也可以进行拦截提示用户
                alert('我是路由独享守卫！！！')
            }
        }
    ]
```

### 3\. 组件内的守卫

```js
import { onBeforeRouteLeave, onBeforeRouteUpdate } from 'vue-router';
        onBeforeRouteUpdate((to,from)=>{//当前组件路由改变后，进行触发
            console.log(to);
        })
        onBeforeRouteLeave((to,from)=>{//离开当前的组件，触发
            alert('我离开啦')
        })
```

## 动态路由

其实就是动态的添加路由配置，需要用到`router`对象的`addRoute`方法该方法接收两个参数：第一个参数是父路由的路由配置对象的`name`属性(可不填)，第二个是你要添加的路由，例如：

```js
// router/index.ts
router.addRoute({
  path: "/detail",
  component: () => import("views/detail.vue"),
});
  // 指定父路由
 router.addRoute('hello',{
  path: "/detail",
  component: () => import("views/detail.vue"),
});
```

## 一个完整的路由配置

一个完整的路由配置`routes.ts`：

```ts
// 路由配置对象
import NotFound from "components/404/index.vue";
export default [
  {
    path: "/",
    name: "main",
    redirect: "/home", // 当为空路由的时候默认重定向到/home所代表的组件
  },
  {
    path: "/home",
    name: "home",
    component: () => import("views/home/index.vue"),
    redirect: "/home/my", // 表示在该页面的router-view中要默认展示的是/my所指向的组件
    children: [
      {
        path: "my",
        name: "my",
        component: () => import("views/home/pages/my.vue"),
      },
      {
        path: "find",
        name: "find",
        component: () => import("views/home/pages/find.vue"),
      },
      {
        path: "cloudVillage",
        name: "cloudVillage",
        component: () => import("views/home/pages/cloudVillage.vue"),
      },
      {
        path: "video",
        name: "video",
        component: () => import("views/home/pages/video.vue"),
      },
    ],
  },
  // 一般放到最后，啥也没匹配到的时候使用404组件
  { path: "/:pathMatch(.*)", name: "notFound", component: NotFound },
];

```

## 和TS结合

一个路由配置模板`route/routes.ts`：

```ts

import { RouteRecordRaw } from "vue-router";
const routes: Array<RouteRecordRaw> = [
  {
    path: "/",
    redirect: "/list",
    name: "main",
  },
  {
    path: "/list",
    name: "list",
    component: () => import(/* webpackChunkName: "list" */ "../views/list.vue"),
  },
  {
    path: "/publish",
    name: "publish",
    component: () =>
      import(/* webpackChunkName: "publish" */ "../views/publish.vue"),
  },
  {
    path: "/:pathMatch(.*)*",
    name: "notFound",
    component: ()=>import(
      /* webpackChunkName: "notFound" */ "../views/notFound.vue"
    ),
  },
];
export default routes;

```
