在软件工程中，我们不仅要创建一致的、定义良好的API，但同时也要考虑到其复用性，组件不仅能支持当前的数据类型，也要支持将来的数据类型，这在创建大型系统的时候为你提供过了十分灵活的功能。

## 定义

说白了,**泛型解决了类型,接口,方法的复用性**,以及对不特定数据类型的支持(类型校验)。

以下属于个人理解：

> 泛型,顾名思义就是泛泛的类型,表示不确定类型,那具体啥时间确定呢?**调用的时候确定**,说白了对于&lt;T,U&gt;中的T和U表示的啥类型只有在调用的时候才确定(无论是类,接口,还是函数)

## 应用

### 泛型函数

在未学泛型之前，我们一个函数一般是这样定义的，例如：

```ts
function getName(name: string): string {
  return name;
}

// getName(1); //报错,因为上面的函数明确规定了参数只能是string类型
getName("谢大脚"); // 谢大脚
```

一个函数的参数类型，返回值的数据类型都确定好了，这就导致该函数的复用性不强，比如，如果我想传入一个数字，返回也是一个数字该咋办，很可能就会重新写一个方法，但是用泛型就不一样了，**其类型是在调用的时候确定的**，例如：

```ts
function _getName<T>(name: T): T {
  return name;
}

_getName<string>("谢大脚");// 将来T的类型就表示string
_getName<number>(9527); // 是不是就很灵活了呢，同理T表示number
```

**当我们调用**`**_getName<string>('谢大脚')**`**，**`**string**`**类型就像参数**`**谢大脚**` **一样，它将在出现**`**T**`**的任何位置填充该类型。**

如果泛型的参数是多个呢，当然也是类似的啦！

```ts
// 比如对于多个参数的泛型也是一样的,比如
function getSum<T, U>(a: T, b: U) {
  return `${a}${b}`;
}

// 一个方法可以延伸出很多的方法,是不是很方便呢?
getSum<string, number>("哈喽", 9527);
getSum<string, string>("哈喽", "谢大脚");
getSum<number, number>(12, 34);
```

如果我们想要返回两种类型的对象怎么办？可以使用元组，例如：

```ts
function identity2<T, U>(value: T, message: U): [T, U] {
  return [value, message];
}
```

还有一种是使用泛型接口，

```ts
// 使用泛型接口定义了一个对象，来约束将来identity3的返回值
interface Identities<T, U> {
  value: T;
  message: U;
}

function identity3<T, U>(value: T, message: U): Identities<T,U> {
  return {
    value,
    message
  }
}

console.log(identity3<string,number>('hello',12));

```

上面的泛型都表示的是基础类型，如果是数组泛型呢？其实也差不多：

```ts
function getGirlName<T>(girlList: T[]) {
  return girlList.forEach((item) => {
    console.log(item);
  });
}
getGirlName<string>(["大脚", "舒畅"]);
```

### 泛型类

先看一下我们在学习泛型之前是咋定义类的吧：

```ts
// 这是一个获取数组中最小值的类
class MinClass {
  public list: number[] = [];
  add(n: number): void {
    this.list.push(n);
  }
  min(): number {
    let min = this.list[0];
    for (var i = 0; i < this.list.length; i++) {
      if (min > this.list[i]) {
        min = this.list[i];
      }
    }
    return min;
  }
}

let minClass = new MinClass(); //{list:[]}
minClass.add(23);
minClass.add(8);
minClass.add(19);
minClass.add(6);
console.log(minClass.min()); // 6
```

但是和函数犯的是同一个毛病，这个类只能传数字，但我想还能传字符串咋办？还是用到泛型，改写如下：

```ts
class MinClass<T> {
  public list: T[] = [];
  add(n: T): void {
    this.list.push(n);
  }
  min(): T {
    let min = this.list[0];
    for (var i = 0; i < this.list.length; i++) {
      if (min > this.list[i]) {
        min = this.list[i];
      }
    }
    return min;
  }
}

let minClass = new MinClass<number>(); //{list:[]}
minClass.add(23);
minClass.add(8);
minClass.add(19);
minClass.add(6);
console.log(minClass.min()); // 6

// 如果T我们传入的是一个string呢，
let minClass2 = new MinClass<string>(); //{list:[]}
minClass2.add('a');
minClass2.add('f');
minClass2.add('g');
minClass2.add('k');
console.log(minClass2.min()); //a
```

还有一种

```ts
// 泛型类
 class GenericNumber<T> {
  zeroValue!: T
  // 只是定义了一种函数类型，具体的实现需要在实例化的时候确定
  add!: (x: T, y: T) => T
 }

//  实例化泛型类
 const myGenericNumber = new GenericNumber<number>()
//  设置泛型值
 myGenericNumber.zeroValue = 0
//  定义函数具体实现
 myGenericNumber.add = function (x, y) {
  return x + y*2
 }
 console.log(myGenericNumber.add(1, 2))
```

 

```ts

  hasMask: boolean = true
}
class ZooKeeper {
  nametag: string = 'Zookeeper'
}
class Animal {
  numLegs: number = 4

class Bee extends Animal {
```

### 泛型接口

以函数接口为例，一般我们在写函数接口的时候是这样的：

```ts
// 接口
interface ConfigFn {
  (val1: string, val2: string): string;
}

let foo: ConfigFn = function (val1: string, val2: string): string {
  return val1 + val2;
};

foo("张", "三");
```

一样的，这样写`ConfigFn`接口定义的函数，参数只能传字符串，但是如果我们还想传数字呢？

我们有两种定义方法：

#### 第一种

```ts
// 函数式接口
interface ConfigFn {
  <T>(val1: T): T;
}
// 定义一个泛型函数getFun，使其符合接口ConfigFn
var getFun: ConfigFn = function <T>(val1: T): T {
  return val1;
};
// 因为getFun是一个泛型函数，所以在调用的时候要明确知道T是啥，所以....
getFun<string>('哈喽')//哈喽
getFun<number>(14)//14
```

#### 第二种

```ts
// 泛型接口
interface ConfigFn1<T> {
  (val1: T): T;
}

// 按照上面的样子写一个符合该要求的函数，这里是具实现
function getFun1<T>(val1: T): T {
  return val1;
}
// 重新定义一个函数myConfigFn满足接口ConfigFn1，但具体的实现是getFun1
// 这时myConfigFn已经是普通函数了（毕竟已经传了number，确定了类型，以后直接调用即可）
let myConfigFn: ConfigFn1<number> = getFun1;

```

那么如果是其他接口呢？其实也是类似的：

```ts
interface Person<T, U> {
  name: U;
  age: T;
  eat(food: U): void;
}
let person: Person<number, string> = {
  name: "谢大脚",
  age: 18,
  eat(food) {
    console.log(food);
  },
};

// person.eat(1); // 报错
person.eat("五谷杂粮");
```

一个典型的泛型接口

```ts
// 泛型接口
// 定义一个类
class CommonInfo {
  sex: string;
  originate: string;
}
// 定义一个泛型接口
interface BaseInfo<T, U, V> {
  name: T;
  age: U;
  commonInfo: V;
  sayInfo(): void;
}
// 泛型接口用在了类上
class UserInfo implements BaseInfo<string, number, CommonInfo> {
  name: string;
  age: number;
  commonInfo: CommonInfo;
  sayInfo(): void {}
  constructor(name: string, age: number, commonInfo: CommonInfo) {
    this.name = name;
    this.age = age;
    this.commonInfo = commonInfo;
  }
}
let userInfo: UserInfo = new UserInfo('张三', 12, { sex: '男', originate: '河南' });
console.log(userInfo);
```

## 条件类型

有点儿像 JS 中的条件表达式，语法如下：

```ts
someType extendes otherType ? trueType:falseType
```

举例说明

```ts
type IsString<T> = T extends string ? 'yes' : 'no'
type I1 = IsString<string> // 'yes'
type I2 = IsString<number> // 'no'

interface Animal1 {
  live():void
}

  howl():void
}

type IsAnimal1<T> = T extends Animal1 ? number : string
// 继承Animal1的接口，返回number

// 不继承Animal1的接口，返回string
type I4 = IsAnimal1<Wolf> // string
```

## 分布式类型

分布式类型是TypeScript中条件类型的一个特性： 当条件类型作用于**联合类型**时，它会分布到联合类型的每个成员上 。

```ts
// 分布式
type ToArray<T> = T extends any ? T[] : never
// string[] | number[]
type StringArrOrNumberArr = ToArray<string | number>
// 执行过程 string extends any？string[],number extends any?number[]
let arr: StringArrOrNumberArr = ['123', '345']
let arr2: StringArrOrNumberArr = [123, 456]

// 非分布式
type ToArray1<T> = [T] extends [any] ? T[] : never

// (string|number)[]
type StringArrOrNumberArr1 = ToArray1<string | number>
let arr3: StringArrOrNumberArr1 = ['123', 456]
```

**为啥要用分布式？**

\- 1. 类型安全 ：确保每个类型成员都得到正确处理

\- 2. 精确控制 ：可以针对联合类型中的特定类型进行过滤或转换

## 默认参数

类似`<T=string,U=number,...>`，表示默认情况下`T`就表示`string`，`U`表示`number`，以此类推

```ts
type A<T = string> = Array<T>;// 类型A默认是字符串数组类型
```

再比如

```ts
// 为泛型参数提供默认类型
interface Pagination<T = any> {
  data: T[];
  total: number;
  page: number;
  size: number;
}

// 使用默认类型
const userPagination: Pagination = { 
  data: [], total: 0, page: 1, size: 10 
};

// 指定具体类型
const productPagination: Pagination<Product> = {
  data: [], total: 0, page: 1, size: 10
};
```

## 泛型支持函数嵌套

比如：

```ts
type CutTail<Tuple extends any[]> = Reverse<CutHead<Reverse<Tuple>>>;
```

如上代码中， Reverse 是将参数列表反转，CutHead 是将数组第一项切掉。因此 CutTail 的意思就是将传递进来的参数列表反转，切掉第一个参数，然后反转回来。换句话说就是切掉参数列表的最后一项。 比如，一个函数是 function fn (a: string, b: number, c: boolean):boolean {}，那么经过操type cutTailFn = CutTail&lt;typeof fn&gt;，可以返回(a: string, b:number) => boolean。 具体实现可以参考Typescript 复杂泛型实践：如何切掉函数参数表的最后一个参数？\[3\]。 在这里，你知道泛型支持嵌套就够了。

## 泛型约束（常见）

**也就是说泛型**`**T**`**的类型不再可以随便给了，你要符合某种要求**，这里的要求其实就是接口`Girl`所指明的，泛型的约束要用到`extends`关键字，后面可以跟一个接口，例如下面的例子：

```ts
// 泛型和接口的结合
interface Girl {
  name: string;
}

// <T extends Girl> 表示将来T所代表的类型必须符合接口Girl的形式,说白了就是一个对象
// 也可以有其他属性，但至少包含name属性
class SelectGirls<T extends Girl> {
  girls: T[];
  constructor(girls: T[]) {
    this.girls = girls;
  }
  getGirl(index: number): void {
    console.log(this.girls[index].name);
  }
}
let selectGirls = new SelectGirls([{ name: "大脚" }, { name: "刘英" }]); // 其实背后使用了类型推断
selectGirls.getGirl(1); // 刘英
```

还有一种约束，例如`<T extends number|string>`表示将来T的类型不能随便给了，你只能在`number`和`string`两者中进行选择,举个很简单的例子：

```ts
// 在函数中
function getVal<T extends number | string>(val: T): T {
  return val;
}
getVal(1);
getVal("哈喽");
getVal(true); //报错
```

在类中的使用，其实和上面的差不多:

```ts
class Boy<T extends number | string> {
  public name: T;
  constructor(val: T) {
    this.name = val;
  }
  sayName() {
    console.log(this.name);
  }
}

let boy = new Boy<string>("刘老四");
let boy1 = new Boy<number>(3);
let boy2 = new Boy<boolean>(true); //Type 'boolean' does not satisfy the constraint 'string | number'
```

## 泛型操作符

### &✨✨✨

& 操作符用于创建 交叉类型(Intersection Types) ，它将多个类型合并为一个新类型，新类型将包含所有类型的特性。

1.  交叉类型使用 & 操作符将多个类型组合在一起，**新类型将具有所有类型的成员**。

```tsx
type TypeA = {
  a: string;
  b: number;
};

type TypeB = {
  c: boolean;
  d: string[];
};

type CombinedType = TypeA & TypeB;
// 等同于:
// {
//   a: string;
//   b: number;
//   c: boolean;
//   d: string[];
// }

const obj: CombinedType = {
  a: 'hello',
  b: 42,
  c: true,
  d: ['item1', 'item2']
};
```

2.  交叉类型与泛型结合使用时，可以创建更加灵活和可复用的类型定义。

```tsx
// 基本泛型交叉类型
type WithId<T> = T & { id: string };

interface User {
  name: string;
  age: number;
}

type UserWithId = WithId<User>;
// 等同于:
// {
//   name: string;
//   age: number;
//   id: string;
// }

const user: UserWithId = {
  name: 'Alice',
  age: 30,
  id: 'user-123'
};

// 更复杂的泛型交叉类型
type WithTimestamp<T> = T & {
  createdAt: Date;
  updatedAt: Date;
};

type FullUser = WithTimestamp<UserWithId>;
// 等同于:
// {
//   name: string;
//   age: number;
//   id: string;
//   createdAt: Date;
//   updatedAt: Date;
// }
```

### as（断言）✨✨✨

运算符 as 的作用可以理解为**改变原有类型定义**，分为以下两种场景：

-   断言
-   转化

#### 断言 JS 数据

```ts
const myStr: any = "tellyourmad";
const myStrLength: number = (someValue as string).length;

```

#### 转化 TS 类型

```ts
type TsUnionType = "a" | "b" | 1 | 2;

// type TsType1 = { a: any; b: any; 1: any; 2: any; }
type TsType1 = {
  [P in TsUnionType]: any;
};

/**
 * 强制将 key 全都 as 成 number 了
 * type TsType2 = { [x: number]: any; }
 */
type TsType2 = {
  [P in TsUnionType as number]: any;
};

```

#### 应用

`as` + `extends` + `in` + `keyof`

所用到的知识点：

-   `keyof` 解构
-   `in` 遍历
-   `extends` 判断
-   `as` 转换

```ts
// 排除特定属性名
type OmitProp<T, R> = {
  [K in keyof T as K extends R ? never : K]: T[K];
  // [K in keyof T as (K extends R ? never : K)]: T[K];
};

// 排除特定属性值
type OmitValue<T, R> = {
  [K in keyof T as T[K] extends R ? never : K]: T[K];
  // [K in keyof T as (T[K] extends R ? never : K)]: T[K];
};

type IOrigin = {
  a: string;
  b: boolean;
  c: number;
  d: string;
};

/**
 * 排除属性名的类型为 "c" | "d" 的属性
 * type IWithoutProp = { a: string; b: string; }
 */
type IWithoutProp = OmitProp<IOrigin, "c" | "d">;

/**
 * 排除属性值的类型为 string | boolean 的属性
 * type IWithoutValue = { c: number; }
 */
type IWithoutValue = OmitValue<IOrigin, string | boolean>;

```

### keyof

keyof 操作符可以用来遍历一个**具体类型【比如接口】**中的所有 key 值, **返回的是这些key值的联合类型**。例如：

```ts
interface Student {
  name: string,
  age: number,
  sex: 'male' | 'female'
}

type Keys = keyof Student // 'name' | 'age' | 'sex'
// 相当于定义了一个联合类型 type Keys = 'name' | 'age' | 'sex'
type Keys = 'name' | 'age' | 'sex' // 也就是将来取值只能是这几个值

```

又例如

```ts
interface Person {
	name:string;
  age:number
}
type K3 = keyof { [x: string]: Person }; // string | number

// 因为这里的键是索引类型，所以是 string | number
```

### in

in用来**遍历枚举类型（联合类型）**，**通常和keyof一起使用**，`keyof`的反向操作

```ts
type Keys = 'a'|'b'|'c'
type Obj = {
    [p in Keys]:number
}
相当于
// type Obj = {
//     a: number;
//     b: number;
//     c: number;
// }
```

### extends

extends 当我们定义的泛型不想过于灵活，或者想**继承某些类的时候**，可以**通过extends关键字添加泛型约束**；

```ts
// 用法1 只想返回一个有length属性值
interface length {
  length: number
}
function getLength<T extends length>(length: T): T {
  return length
}
getLength('123')
getLength([1,2,3])

```

### 三元表达式

又比如还可以这样继承，使用三元表达式

```ts
 T extends U ? X : Y;
```

可以这样理解：`T`是`U`的子类型，那么返回结果是`Y`, 否则是`N`. 类似`JS`中的三元表达式，其工作原理是类似的，例如：

```ts
type res1 = true extends boolean ? true : false                  // true
type res2 = 'name' extends 'name'|'age' ? true : false           // true
type res3 = [1, 2, 3] extends { length: number; } ? true : false // true
type res4 = [1, 2, 3] extends Array<number> ? true : false       // true

```

又比如题目来源于[type-challengs](https://github.com/Shawshank8815/type-challenges/blob/main/questions/00268-easy-if/README.md)：

```ts

// type B = If<false, 'a', 'b'> // expected to be 'b'
type If<C, T, F> = C extends true ? T : C extends false ? F : never;

type A = If<true, "a", "b">;
type B = If<false, "a", "b">;
type C = If<'dadada', "a", "b">;
```


### infer🐸🐸🐸

`infer` 是 TypeScript 中的一个关键字，它只能在条件类型的 `extends` 子句中使用，用于**推断**一个类型变量。简单来说，`infer` 允许我们从一个类型中提取和捕获一部分类型信息，并将其赋值给一个变量，以便在类型系统中进一步使用。

#### 一、基本语法

```ts
type MyType<T> = T extends infer U ? U : never;
```

这里的 `infer U` 表示我们想要从类型 `T` 中推断出一个类型，并将其命名为 `U`。

#### 二、常见使用场景与示例

##### 1\. 提取函数返回类型

最常见的用途之一是提取函数的返回类型：

```ts
// 标准库中的 ReturnType 实现
type ReturnType<T extends (...args: any[]) => any> = T extends (...args: any[]) => infer R ? R : any;

// 使用示例
function getUser() { return { name: 'Alice', age: 25 }; }
type User = ReturnType<typeof getUser>; // { name: string; age: number }
```

##### 2\. 提取函数参数类型

```ts
// 提取第一个参数类型
type FirstParamType<T> = T extends (first: infer U, ...args: any[]) => any ? U : never;

// 使用示例
type FirstArg = FirstParamType<(id: number, name: string) => void>; // number
```

##### 3\. 提取数组元素类型

```ts
type ArrayElementType<T> = T extends Array<infer U> ? U : never;

// 使用示例
type Element = ArrayElementType<string[]>; // string
```

##### 4\. 提取 Promise 类型

```ts
type PromiseType<T> = T extends Promise<infer U> ? U : T;

// 使用示例
type Data = PromiseType<Promise<{ id: number }>>; // { id: number }
```

##### 5\. 类型转换与解构

```ts
// 交换元组类型的元素
type Swap<T> = T extends [infer A, infer B] ? [B, A] : T;

// 使用示例
type Swapped = Swap<[string, number]>; // [number, string]
```

#### 三、高级应用模式

##### 1\. 递归推断

可以结合递归来处理更复杂的类型结构：

```ts
// 提取嵌套数组的元素类型
type DeepArrayElementType<T> = T extends Array<infer U> 
  ? DeepArrayElementType<U> 
  : T;

// 使用示例
type DeepElement = DeepArrayElementType<string[][]>; // string
```

##### 2\. 多重推断

在一个条件类型中可以使用多个 `infer` 来提取不同的类型部分：

```ts
// 同时提取函数的参数类型和返回类型
type FunctionInfo<T> = T extends (...args: infer A) => infer R
  ? { args: A; returnType: R }
  : never;

// 使用示例
type Info = FunctionInfo<(x: number, y: string) => boolean>;
// { args: [number, string]; returnType: boolean }
```

##### 3\. 联合类型的分配性

当 `infer` 用于联合类型时，会表现出分配性（distributive）：

```ts
// 提取联合类型中所有函数的返回类型
type UnionReturnTypes<T> = T extends (...args: any[]) => infer R ? R : never;

// 使用示例
type Returns = UnionReturnTypes<(() => string) | (() => number)>; // string | number
```

#### 四、注意事项

1.  `infer` 只能在条件类型的 `extends` 子句中使用，不能在其他地方使用
2.  同一条件类型中可以使用多个 `infer` 关键字来推断不同的类型部分
3.  在联合类型上使用时，`infer` 会表现出分配性
4.  `infer` 变量的作用域仅限于它所在的条件类型分支

#### 五、实用工具类型示例

TypeScript 标准库中许多实用工具类型都使用了 `infer`：

```ts
// Parameters<T> - 提取函数参数类型为元组
type Parameters<T extends (...args: any[]) => any> = T extends (...args: infer P) => any ? P : never;

// ConstructorParameters<T> - 提取构造函数参数类型
type ConstructorParameters<T extends abstract new (...args: any[]) => any> = 
  T extends abstract new (...args: infer P) => any ? P : never;

// InstanceType<T> - 提取构造函数的实例类型
type InstanceType<T extends abstract new (...args: any[]) => any> = 
  T extends abstract new (...args: any[]) => infer R ? R : any;
```

通过这些示例可以看出，`infer` 是 TypeScript 类型系统中非常强大的工具，它极大地增强了类型操作的灵活性和表达力，使我们能够编写更精确、更通用的类型工具。

#### Exclude

Exclude 操作符会从类型 `T` 中排除所有可以赋值给类型 `U` 的类型，返回剩余的类型。

##### 语法

```ts
Exclude<T,U>

```

##### 例子

```ts
type T = string | number | boolean;
type U = string;

type Result = Exclude<T, U>;  // number | boolean

// 更复杂的例子
type EventType = 'click' | 'scroll' | 'mousemove' | 'keydown';
type UIEvent = Exclude<EventType, 'keydown'>;  // 'click' | 'scroll' | 'mousemove'
```

##### 使用场景

```ts
type Animal = 'dog' | 'cat' | 'bird' | 'fish';
type Pet = Exclude<Animal, 'fish'>;  // 'dog' | 'cat' | 'bird'

function handlePet(pet: Pet) {
  console.log(`Handling pet: ${pet}`);
}

handlePet('dog');    // 正确
handlePet('cat');    // 正确
handlePet('bird');   // 正确
// handlePet('fish'); // 错误：参数类型 '"fish"' 不能赋给类型 'Pet'
```

 

```ts
type NullableString = string | null | undefined;
type NonNullString = Exclude<NullableString, null | undefined>;  // string

function processString(str: NonNullString) {
  // 在这里，str保证不是null或undefined
  return str.toUpperCase();
}

const input: NullableString = "hello";
if (input !== null && input !== undefined) {
  processString(input);  // 需要类型断言或类型保护
}
```

##### 高级用法

```ts
type T = string | number | boolean | null | undefined;
type U = string | number | null;

type Result = Exclude<T, U>;  // boolean | undefined
```

 

```ts
interface Dog {
  type: 'dog';
  bark: () => void;
}

interface Cat {
  type: 'cat';
  meow: () => void;
}

interface Fish {
  type: 'fish';
  swim: () => void;
}

type Animal = Dog | Cat | Fish;

// 排除所有有bark方法的类型
type NonBarkingAnimals = Exclude<Animal, { bark: () => void }>;  // Cat | Fish
```

##### 关于 U

在 `Exclude<T, U>` 中， `U` 可以是任何TypeScript类型，包括但不限于：

1.  基本类型（如 `string` 、 `number` 、 `boolean` ）
2.  字符串字面量类型（如 `'click'` 、 `'scroll'` ）
3.  联合类型（如 `string | number` 、 `'click' | 'keydown'` ）
4.  对象类型（如 `{ status: 'loading' }` 、 `{ bark: () => void }` ）
5.  函数类型（如 `Function` 、 `() => void` ）
6.  特殊类型（如 `null` 、 `undefined` 、 `any` 、 `never` ）

`U` 的类型决定了从`T` 中要排除的内容，只要 `T`中的某个类型可以赋值给`U` ，该类型就会被排除。这种灵活性使得 `Exclude` 成为一个非常强大的类型操作工具，可以用于各种复杂的类型操作场景。

#### Extract

**和** `**Exclude**` **相反**，`Extract` 操作符会从类型 `T`中提取所有可以赋值给类型 `U` 的类型，返回这些类型的联合。

##### 语法

```ts

```

##### 基本使用

```ts

handlePet('cat');    // 正确

// handlePet('fish'); // 错误：参数类型 '"fish"' 不能赋给类型 'Pet'
```

 

```ts

    console.log('Value is not nullable');
```

```ts
  enableLogging: true 
}); // 覆盖多个属性
```

#### Required

Required 的作用就是将某个类型中的属性**全部变为必选**，并返回新的类型

##### 语法

```ts
Required<Type>
```

例子

```ts
interface User {
  id: number;
  name: string;
  email?: string;  // 可选属性
  age?: number;    // 可选属性
}

const requiredUser: Required<User> = {
  id: 1,
  name: "张三",
  email: "zhangsan@example.com",  // 现在是必需的
  age: 25  // 现在是必需的
};

// 以下会导致编译错误，因为缺少必需的属性
// const incompleteUser: Required<User> = {
//   id: 1,
//   name: "张三"
//   // 错误：类型中缺少属性 "email" 和 "age"
// };
```

##### 使用场景

```ts
interface CreateUserParams {
  username: string;
  password: string;
  email?: string;
  phone?: string;
}

function createUser(params: Required<CreateUserParams>): User {
  // 在函数内部，可以安全地访问所有属性
  const { username, password, email, phone } = params;
  
  // 创建用户逻辑
  return {
    id: Math.random(),
    username,
    password,
    email,
    phone
  };
}

// 调用函数前需要确保所有参数都有值
const params: CreateUserParams = {
  username: "zhangsan",
  password: "123456",
  email: "zhangsan@example.com",
  phone: "13800138000"
};

const user = createUser(params as Required<CreateUserParams>);
```

#### ReturnType

用于**获取函数的返回值类型**。它通过分析函数定义自动推导出返回值的类型，从而在类型检查和推断中提供准确信息。

```tsx
function add(a: number, b: number): number {  
  return a + b;  
}  
type addReturnType = ReturnType<typeof add>; // 返回类型为number  

```

#### NonNullable

`NonNullable` 操作符用于从类型`T`中排除`null`和`undefined`

```ts
type T = string | number | null | undefined;
type NonNullableT = NonNullable<T>; // string | number

function printValue(value: NonNullable<T>) {
  console.log(value);
}

printValue('hello'); // OK
printValue(42); // OK
printValue(null); // Error
printValue(undefined); // Error
```

#### Parameters

`Parameters` 操作符用于**提取函数类型**`**T**`**的参数类型**，**返回一个元组类型。**

```ts
function createUser(name: string, age: number, isAdmin: boolean): User {
  return { name, age, isAdmin };
}

type CreateUserParams = Parameters<typeof createUser>;
// 等同于 type CreateUserParams = [name: string, age: number, isAdmin: boolean];

function logUserCreation(...params: CreateUserParams) {
  console.log(`Creating user with params: ${params.join(', ')}`);
}

logUserCreation('Alice', 30, true);
```

#### InstanceType

`InstanceType` 操作符用于提取构造函数类型`T`的实例类型。

```ts
class User {
  constructor(public name: string, public age: number) {}
}

type UserInstance = InstanceType<typeof User>;
// 等同于 type UserInstance = User

function processUserInstance(user: UserInstance) {
  console.log(`User: ${user.name}, Age: ${user.age}`);
}
```

#### ThisType

`ThisType<T>` 操作符用于**指定函数内this的类型**，**它不返回转换后的类型**，而是在对象字面量中标记this的类型。

```ts
interface User {
  name: string;
  age: number;
  greet: (this: User) => void;
}

const user: User & ThisType<User> = {
  name: 'John',
  age: 30,
  greet() {
    console.log(`Hello, my name is ${this.name}`); // this被正确推断为User类型
  }
};
```

#### Uppercase

`Uppercase` 操作符将字符串字面量类型转换为大写。

```ts
type Greeting = 'hello';
type LoudGreeting = Uppercase<Greeting>; // 'HELLO'

type EventNames = 'click' | 'scroll' | 'mousemove';
type LoudEventNames = Uppercase<EventNames>; // 'CLICK' | 'SCROLL' | 'MOUSEMOVE'
```

#### Lowercase

`Lowercase` 操作符将字符串字面量类型转换为小写

```ts
type Greeting = 'HELLO';
type QuietGreeting = Lowercase<Greeting>; // 'hello'

type EventNames = 'CLICK' | 'SCROLL' | 'MOUSEMOVE';
type QuietEventNames = Lowercase<EventNames>; // 'click' | 'scroll' | 'mousemove'
```

#### Capitalize

`Capitalize` 操作符将**字符串字面量类型的首字母转换为大写**。

```ts
type Greeting = 'hello';
type FormalGreeting = Capitalize<Greeting>; // 'Hello'

type Actions = 'create' | 'update' | 'delete';
type FormalActions = Capitalize<Actions>; // 'Create' | 'Update' | 'Delete'
```

#### Uncapitalize

`Uncapitalize` 操作符将字符串字面量类型的首字母转换为小写。

```ts
type Greeting = 'Hello';
type InformalGreeting = Uncapitalize<Greeting>; // 'hello'

type Actions = 'Create' | 'Update' | 'Delete';
type InformalActions = Uncapitalize<Actions>; // 'create' | 'update' | 'delete'
```

#### Awaited

`Awaited<T>` 操作符用于**提取** `**Promise**` **的解析类型**，特别是对于嵌套的 `Promise`。

```ts
type A = Awaited<Promise<string>>; // string
type B = Awaited<Promise<Promise<number>>>; // number

async function getUser(): Promise<{ name: string; age: number }> {
  return { name: 'John', age: 30 };
}

type UserType = Awaited<ReturnType<typeof getUser>>; // { name: string; age: number }
```

#### ConstructorParameters

`ConstructorParameters<T>` 操作符用于提取构造函数类型的参数类型。

```ts
class User {
  constructor(public name: string, public age: number) {}
}

type UserConstructorParams = ConstructorParameters<typeof User>;
// 等同于 type UserConstructorParams = [name: string, age: number];

function logUserCreation(...params: UserConstructorParams) {
  console.log(`Creating user with params: ${params.join(', ')}`);
}

logUserCreation('Alice', 30);
```

#### 递归

```ts
// 深度可选
type DeepPartial<T> = {
  [P in keyof T]?: T[P] extends object ? DeepPartial<T[P]> : T[P]
}

// 深度只读
type DeepReadonly<T> = {
  readonly [P in keyof T]: T[P] extends object ? DeepReadonly<T[P]> : T[P]
}

// 深度必需
type DeepRequired<T> = {
  [P in keyof T]-?: T[P] extends object ? DeepRequired<T[P]> : T[P]
}
```

## 啥时候用泛型

当你的函数，接口或者类：

-   需要作用到很多类型的时候，比如我们介绍的 id 函数的泛型声明。
-   需要被用到很多地方的时候，比如我们介绍的 Partial 泛型。

## 总结

在TS中，最重要也是最难的就是泛型，有句话这么说“真正的高手都是各种花式操作泛型”：

> 随着在 TS 方面学习的深入，越来越认识到 **「真正的 TS 高手都是在玩类型」**，对类型进行各种运算生成新的类型。这也好理解，毕竟 **「TS 提供的其实就是类型系统」**。你去看那些 TS 高手的代码，会各种**「花式使用泛型」**。 可以说泛型是一道坎，只有真正掌握它，你才知道**「原来 TS 还可以这么玩」**。怪不得面试的时候大家都愿意问泛型，尽管面试官很可能也不怎么懂。

自我感觉，泛型能够极大的扩展函数、接口、类的通用性以及可复用性，能够让我们以最少的代码实现更多的功能，就像下文中说的那样：

> 也就是说泛型也是一种类型，只不过不同于 string, number 等具体的类型，它是一种抽象的类型，我们不能直接定义一个变量类型为泛型。

> 学习 Typescript 并不是一件简单的事情，尤其是没有其他语言背景的情况。而 TS 中最为困难的内容之一恐怕就是泛型了。
> 
> **泛型和我们平时使用的函数是很像的，如果将两者进行横向对比，会很容易理解，很多函数的都关系可以迁移到泛型，比如函数嵌套，递归，默认参数等等。**泛型是对类型进行编程，参数是类型，返回值是一个新的类型。我们甚至可以对泛型的参数进行约束，就类似于函数的类型约束。
> 
> 最后通过几个高级的泛型用法以及若干使用的泛型工具类帮助大家理解和消化上面的知识。要知道真正的 TS 高手都是玩类型的，高手才不会满足于类型的交叉并操作。 泛型用的好确实可以极大减少代码量，提高代码维护性。如果用的太深入，也可能会团队成员面面相觑，一脸茫然。因此抽象层次一定要合理，不仅仅是泛型，整个软件工程都是如此。
